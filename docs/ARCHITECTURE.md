# Observatory Core architecture

The SDK (OC-A01) solely implements record validation, ingestion, provenance, retrieval, research tools, audit primitives and publication candidate preparation. The CLI (A02) calls supported SDK imports. The initial loopback API (A03) and local MCP (A04) hosts adapt authenticated requests to SDK operations; the offline Linux container candidate (A05) packages the SDK and existing hosts. No interface owns a second engine or approval policy.

`src/core/` and `schemas/core/0.1.0/` hold neutral records/stores; `src/discovery/newsroom.mjs` owns `gc.discovery/1`; `src/ingestion/` handles feeds/transport; `src/research/` owns archive, citations, read-only tools, audit and experimental integration/JSON transport. `src/contract.mjs`, `src/classification.mjs` and `src/publish.mjs` preserve legacy GC publication v1. The standalone private observatory-core package exposes a root SDK entry point; historical deep paths remain accessible.

Untrusted sources enter bounded adapters; a locator is not fetch authorization. Captures/evidence preserve provenance and versions. Citations must resolve to retained content. Hosts supply authenticated context, candidate scope, policy and durable audit. SDK output is a candidate; external authorities approve and publish. The local Portal-style fixture (`OC-INT-06-GOVERNED-FIXTURE.md`) does not prove live Portal integration. Preserve `oc.research.v1`, GC publication v1 and `gc.discovery/1` by explicit versioning and compatibility tests.

Observatory Core is independently governed by its owner, Osprey Strategic Holdings LLC. CRA provides delivery assurance; ZTA is a separate assessment methodology. Governance Commons is an optional consumer and specification source for explicitly implemented GC contracts, not product authority or a general release framework. Assess GC conformance only for claimed GC integration contracts. `src/integrations/time-loc.mjs` is an optional adapter to the canonical time.loc primitive, not a new OC timestamp authority. Keep temporary artifacts in this repository's `.scratch`. This repo records acceptance and evidence pointers, not a competing governance authority. Cross-repo changes require separately scoped work.
