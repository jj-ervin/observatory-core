# Observatory Core architecture

The SDK (OC-A01) solely implements record validation, ingestion, provenance, retrieval, research tools, audit primitives and publication candidate preparation. The CLI (A02) calls supported SDK imports. Future API (A03) and MCP (A04) hosts adapt authenticated requests to SDK operations; a future container (A05) packages a chosen host and SDK. No interface owns a second engine or approval policy.

`src/core/` and `schemas/core/0.1.0/` hold neutral records/stores; `src/discovery/newsroom.mjs` owns `gc.discovery/1`; `src/ingestion/` handles feeds/transport; `src/research/` owns archive, citations, read-only tools, audit and experimental integration/JSON transport. `src/contract.mjs`, `src/classification.mjs` and `src/publish.mjs` preserve legacy GC publication v1. The package currently exposes source paths without a declared stable top-level SDK entry point.

Untrusted sources enter bounded adapters; a locator is not fetch authorization. Captures/evidence preserve provenance and versions. Citations must resolve to retained content. Hosts supply authenticated context, candidate scope, policy and durable audit. SDK output is a candidate; external authorities approve and publish. The local Portal-style fixture (`OC-INT-06-GOVERNED-FIXTURE.md`) does not prove live Portal integration. Preserve `oc.research.v1`, GC publication v1 and `gc.discovery/1` by explicit versioning and compatibility tests.

Reuse Governance Commons DEV-ACCORD and capability-contract vocabulary, CRA delivery assurance and applicable GC conformance profiles. The WFQ architecture decision places governance authority with GC and adopters, temporary output with each project, and does not require a universal facility manifest or WFQ adoption for CRA. `src/integrations/time-loc.mjs` is an optional adapter to the canonical time.loc primitive, not a new OC timestamp authority. Keep temporary artifacts in this repository's `.scratch`. This repo records acceptance and evidence pointers, not a competing governance authority. Cross-repo changes require separately scoped work.
